# Nova reference guide

[← Back to Nova](../README.md) · [Developer guide](development.md)

Detailed controls, file behavior, voice typing, and current limits. For a quick introduction, start with [Your first few minutes](../README.md#your-first-few-minutes).

## Use

- **Open Folder** (Command-O / Ctrl-O): open an ordinary local folder in a new window and browse Markdown (`.md`, `.markdown`, and `.mdx`, without JSX) and UTF-8 text files, including custom extensions and extensionless files. No vault is required. Custom file types are screened for text content before appearing in the explorer. Local directories load as you expand them, in pages of 300 entries; use **Load more** for additional entries. Opening a large folder does not scan its entire tree.
- **Source / Edit / Read**: Source edits raw Markdown. For Markdown notes up to 500,000 characters, Edit and Read share the same document layout, including headings, formatted text, nested lists, tasks, quotes, code blocks, and tables. Edit adds a formatting toolbar and direct text editing; Read only allows task checkboxes to change. Tab/Shift-Tab nest and outdent list items. Switching modes does not rewrite the file; checkbox toggles change only the check character. Unsupported constructs remain intact and can be edited in Source. Larger Markdown notes use source editing and a chunked reader, with continuous scrolling or pages. Files selected in visible panes are loaded; other tabs retain their saved editor state.
- Click the **Cloud** or **Local** section label and chevron to expand or collapse that section. Each section remembers its state; switching to a note reveals its section and parent folders. Local has a **folder-open icon** for **Open Folder**, and the folder beneath it can also collapse. All folder-open buttons, **Recent** selections, and folder drops open a separate window, leaving the current folder and unsaved edits in place. **Recent** is hidden when there are no other recent folders and offers a command to clear the list. Each folder remembers its tabs, active note, mode, and expanded directories. **Close Folder** returns it to Recents without deleting any files. Drop one folder from Finder/Explorer to open it. Existing multi-folder sessions migrate to one focused local folder, with the others in Recents. Cloud spaces remain persistent and can still be reordered. Sessions are stored in app-data `explorer.json`; recent local folders are not loaded at startup. Folder errors show their cause, and an inaccessible subdirectory can be retried without closing the workspace.
- **Command-K / Ctrl-K**: search filenames, bookmark names and excerpts, and saved file contents. Use All / Files / Bookmarks / Text / Settings filters, arrows and Enter to navigate, and Escape to close. Results include their folder; text results open at their line in Source mode. The Settings filter lets you find preferences and choose their values; All also includes matching settings when you type. See [Search](#search) for matching options and path filters.
- **Command-F / Ctrl-F**: toggle find within the active editor panel, with match counts and Enter / Shift-Enter navigation. Each split panel keeps its own find bar and query while its note stays mounted. Formatted Edit and Read keep the current view, highlight matches, and scroll to each result; the current match has a stronger highlight. In formatted Edit, use the arrow beside Find to show **Replace with**, **Replace**, and **Replace all**. Enter in the replacement field replaces the current match; empty replacement text deletes matches. Replacement text is literal, and Replace All is one undo step. In Read, switch to Edit to enable replacement. In Source, expand **Search options & replace** for case-sensitive, whole-word, or regex matching, selecting all matches, and replacing one or all matches. Escape also closes find; reopening retains the query while the editor stays mounted.
- **Search scope**: Everywhere searches this window’s local folder and Cloud spaces; Current tab searches the focused note, including unsaved edits, and jumps without saving or reloading. The scope is remembered for the session and Current tab is disabled without an open note.
- **Command-Shift-B / Ctrl-Shift-B**: bookmark a selection or the current line, or use the bookmark button beside the active Source line. In formatted Edit and Read, the active nonempty passage and saved passages have bookmark buttons beside them; click an outline to add a named bookmark or a filled icon to remove it. Source bookmarks can also be removed by clicking their filled gutter icon. Bookmark controls sit separately from list bullets, numbers, and task checkboxes. Name, rename, remove, preview, and jump from the right rail. Switch between Current tab and All bookmarks to browse passages across the focused local folder and Cloud spaces. Read-mode selection works when the selected visible text maps directly to Markdown source.
- **Command-S / Ctrl-S**: save. Local notes keep recovery drafts when switching files or quitting without writing edits to the original file. Cloud notes autosave on the device and queue uploads automatically. Closing an unsaved tab asks whether to save, discard, or cancel. Bookmark edits are retained with the draft until Save.
- **Command− / Ctrl−** and **Command+ / Ctrl+**: zoom the interface out or in (50–200%). Command= / Ctrl= also zooms in; Command-0 / Ctrl-0 resets to 100%.
- **New note**: hover over the local folder’s row (or focus its controls with the keyboard) and click **+** to create a note in that folder, even while viewing a Cloud note. The button stays visible on touch devices. You can also click the bottom-left navigation **+**, click the new-tab + button, or press Command-T / Ctrl-T to create `Untitled.md` in the active folder (or the first available folder) on a new installation. Settings offers a default-extension picker with formats such as `.txt`, `.json`, and `.py`. Existing preferences, including custom extensions, are preserved. Existing names get a numeric suffix. Markdown notes default to Edit; other text files default to Source. Your last chosen mode is remembered per file extension across folders; extensionless files share their own preference. Closing an untouched empty untitled note created in the current session removes its empty file; notes with drafts, content, or a new name are retained.
- **Rename**: click the title above the note to edit its name without changing the extension. The caret starts at the clicked position when the browser can resolve it; keyboard activation places it at the end. Enter, Command-S / Ctrl-S, or leaving the title saves; Escape cancels. The title scrolls with the note and hides the extension. To change the extension too, use the pencil beside a file, right-click → **Rename…**, or double-click a fixed tab. The dialog separates the file name and extension and previews the destination path. Enter applies; Escape cancels. Renaming within Nova carries bookmarks, stars, drafts, and the open tab to the new name.
- **File actions**: use **Open in File Location** above the note to reveal its file in Finder/Explorer (desktop files only). Alternatively, right-click a file to move it to an existing directory within the same root, reveal it in Finder/Explorer, or permanently delete it after confirmation. Moving carries bookmarks, stars, drafts, and tabs; deleting removes the file and its saved bookmarks.
- **Explorer filters**: use the header’s cloud button to show only files selected for sync. Combine it with the star filter to show files matching both. Selection does not mean an upload has completed.
- **Starred files**: toggle the star in the top breadcrumb bar. At the top of the Bookmarks panel, choose the **star icon** to jump directly to saved files across the focused local folder and Cloud spaces, including files inside collapsed directories. Single-click a starred file to open a flex tab; double-click it to make the tab permanent. Each entry shows its path and lets you remove its star. Choose the **bookmark icon** to return to text bookmarks. The **Bookmark a passage** button and first-bookmark guidance sit at the bottom of that view. Both views separate **Cloud** and **Local** into collapsible sections, with each section’s open state remembered independently. Stars are stored as relative paths in a `.nova` JSON file at each root; this registry opens in a normal tab with metadata validation when hidden files are shown.
- **New window**: Command-N / Ctrl-N opens another Nova window on the welcome screen, with the same focused local folder, Cloud spaces, and Recents, but no restored tabs.
- **External Local changes**: on desktop, native filesystem notifications trigger checks of affected open Local files and root/expanded directory listings. Bursts such as Git checkouts are combined into batches. There is no recurring folder scan. Clean notes reload automatically; folder listings retain already loaded pages. While the window is hidden or a save is running, changes wait for a safe refresh. Returning to the window also checks for missed changes. Changed or deleted files with unsaved edits keep their open copy and recovery draft, with a notice. Saves still check the original disk revision. **Refresh folder** remains available for a manual reload of the root and expanded directories.
- **Google Drive**: use the cloud button beside Settings to connect. Desktop separates Local folders from Cloud spaces; iOS uses Cloud only. Connecting automatically discovers and downloads your Cloud spaces. Cloud notes autosave and sync, with checks every minute while active and on return to the foreground; the focused Cloud note is checked every five seconds. Local notes stay local unless you choose **Move to Cloud…**. Cloud deletion removes only this device's copy and retains the Drive file. See [Google Drive](sync.md) for setup, conflict handling, and current limits.

Bookmarks live in Tauri's OS app-data directory, under `com.nova.notes.prototype/bookmarks`, keyed by canonical file path. They never add markup or metadata to notes folders. They follow edits using CodeMirror transaction mappings. On reopen, stored excerpts recover moved passages; missing excerpts are flagged. Renaming/moving a file outside Nova does not yet migrate its bookmarks. Deleted-anchor recovery through Undo is not implemented.

Saves compare the disk revision before writing and use a temporary file plus atomic replacement. A detected external change prevents the save and keeps edits open. Recovery drafts retain their original disk revision, so restoring a draft does not bypass conflict checks. Copy edits to a safe place and reconcile external changes when there is a conflict; reopening restores the draft. CRLF line endings are preserved for CRLF documents; mixed line endings normalize. Atomic replacement may not preserve all extended file attributes. This prototype is not a collaborative editor or a backup system.

## Workspace metadata

Files and folders whose names start with `.` are hidden in global navigation by default. Hover over the **Local** header or focus its controls to reveal the **eye button** beside Recent and Open Folder; on touch devices it stays visible. Toggle it to show or hide dot paths, including `.git` and `.obsidian`. **Show hidden files and folders** in Settings and Command-K / Ctrl-K settings controls the same remembered navigation preference. Search has an independent **Advanced search → Include hidden files and folders** checkbox, off by default and remembered per workspace. It applies to filename, text, and bookmark results, including paths inside hidden folders. Neither visibility option changes sync rules. Binary files, `node_modules`, `target`, Nova temporary files, and registry backups remain excluded. Use **Refresh folder** if a newly created file is not yet listed.

With hidden files shown, click the root `.nova` file to open a normal editor tab with JSON syntax highlighting and inline validation. Tabs can be pinned and moved between editor panels as usual. Use **Save** or Command-S / Ctrl-S explicitly; metadata never autosaves, even inside a Cloud space. Unsaved edits use normal recovery drafts and the standard save/discard/cancel prompt when closing a changed tab. Rename, move, delete, star, bookmark, and sync actions remain unavailable.

Validation blocks saving malformed JSON, a non-object root, invalid starred paths, and invalid sync choices, and explains the problem. JSON syntax errors include line and column information. Custom fields are preserved. Cloud identity and tracking fields (such as `cloudSpace`, `driveWorkspace`, `driveObjects`, and registry versions) are visible but cannot be changed here; use Nova’s Cloud controls. The editor accepts regular UTF-8 files up to 4 MiB and refuses symbolic links.

Saves check that `.nova` still matches the version opened, including changes made by Nova’s own starring or sync operations. On conflict, copy your edits somewhere safe, close the tab and explicitly discard its changes, then reopen the file and reapply your edits. A save refreshes the workspace’s stars and sync choices. The editor handles existing metadata in an open workspace; it does not bypass errors that prevent a damaged workspace from opening.

## Search

The navigation header’s **Quick find** button uses a command icon and opens the Command-K / Ctrl-K palette for files, bookmarks, text, and commands. Below it, the folder icon opens **Files** and the magnifying glass opens **Search across files**. Both icon buttons have hover labels and highlight the active view.

**Command-Shift-F / Ctrl-Shift-F** opens the **Search** panel beside Files in the left sidebar. It searches saved content across this window’s folders, groups results by file, and opens a result at its matching line. Use the arrow beside Find to reveal replacement controls; **Advanced** contains inclusion/exclusion patterns and hidden-file search. Escape returns to Files; reopening Search retains its query. **Command-F / Ctrl-F** remains the focused note’s Find command.

**Command-P / Ctrl-P** opens filename search across this window’s local folder and Cloud spaces. **Command-K / Ctrl-K** opens the broader palette for files, bookmarks, text, and settings. **Everywhere** searches saved file content; **Current tab** includes unsaved edits in the active note.

Use **Match case**, **Match whole word**, or **Use regular expression** beside the query to change matching. Invalid expressions show an error; the native search engine may reject expressions unsupported by its regex syntax. These matching controls do not apply to Settings results.

Expand **Advanced search** for **Files to include** and **Files to exclude**. Enter comma-separated paths or patterns relative to each folder: `*.md` limits results to Markdown files, `notes/**` includes a subtree, and `archive/**, *.log` excludes archived files and logs. `*` matches within a name and `**` spans nested folders. Clear the fields to remove path filtering; a **Filters active** badge remains visible when the controls are collapsed.

Matching options, path filters, and whether Advanced search is expanded are saved on this device for the workspace’s set of folders. Changing between Current tab and Everywhere does not reset them.

### Replace across files

Open **Search** beside Files (Command-Shift-F / Ctrl-Shift-F), expand the arrow beside Find, enter the search and replacement text, and choose **Preview replacements**. Command-K / Ctrl-K’s **Everywhere → Replace** also opens this panel with the palette query. Expand **Review before and after** for each file, uncheck files you want to keep, then choose **Replace in … selected files**. Each selected file is saved immediately; this is not a single editor undo operation. An empty replacement deletes matches. Replacement text is literal, including `$1` and `$&`; regex matching does not expand capture groups in the replacement.

Matching uses the case, whole-word, regex, include/exclude, and hidden-file search controls. Preview covers up to 100 candidate files and four million combined before/after characters, with at most 10,000 replacements per file; warnings explain when it stops. Narrow the include filter to cover remaining files. Changing the query, replacement, or filters requires a new preview. Leaving the Search panel, collapsing Replace, or changing its search stops any remaining queued replacements; files already saved stay changed.

Only saved **Local** files are eligible. Cloud spaces, dirty open notes, recovery drafts, workspace metadata, and symbolic links are excluded or rejected. A file changed on disk since preview is rejected and can be previewed again. Bookmarks follow replacements, including changed passage text; deleting a whole passage retains an unresolved bookmark. Results report successful files and individual failures. Clean open desktop notes refresh through external-change detection. Browser sample notes have no filesystem watcher; open sample tabs are excluded from replacement.

### Heading outline

Choose **Heading outline** beside Starred files and Passages in the right panel. The outline lists the active Markdown note's headings by level, including unsaved edits. Click a heading to jump to it in Source, Edit, or Read without changing modes. It also works with the large-note reader and paginated reading. Duplicate headings remain separate entries.

Only Markdown notes have an outline. Notes without headings show an empty state. The outline updates after a brief typing pause and initially displays 200 headings; **Show more headings** reveals the next group. Heading markers inside code blocks are not included.

## Workspace and formatting

Open **Settings** from the sidebar or with Command-comma / Ctrl-comma. Preferences save automatically on this device: Galaxy mode, editor font, editor text size, text width, line spacing, line numbers, line highlight, word wrap, spellcheck, bookmark-panel visibility, and the default extension for new files. Font, text width, text size, and line spacing apply to Source, Edit, and Read. Choose **Default**, **DM Sans**, **Lora**, **System**, or **Monospace** using **Font** in Settings or the **View** menu above the note. Default preserves each mode’s original typography. **Text size** is also available in both places, with Small, Default, Large, and Extra large options. Choose Compact, Default, Relaxed, or Spacious line spacing in Settings or the **View** menu. The toolbar’s text-width and line-spacing menus support arrow keys, Home/End, and Escape, returning focus to the trigger after a selection. With Galaxy mode enabled, the **Background** button cycles through **Translucent**, **Black**, and **Frosted** for the page. **Frosted panels** toggles the surrounding panels independently; both choices are remembered. Native desktop blur follows the visible regions on macOS. On Windows, Frosted is unavailable: the page offers Translucent or Black, panels stay Black, and previously saved Frosted choices display as Black. Reduced-transparency preferences disable the blur. Line numbers are available in the source editor. Line highlighting is off by default for new preferences; enable it in the toolbar or Settings to highlight the active line in Source or the selected visual line in formatted Edit/Read. Existing saved preferences are retained.

**Settings → Show Read mode** adds Read to the view switch on desktop and mobile. It defaults off, including on existing installations. With it off, saved Read sessions open in Edit for Markdown or Source for other files; disabling it also switches open reading tabs to their editing view. Markdown notes over 500,000 characters retain access to the reader independently of this setting.

When Read is available, **View → Reading layout** switches Read mode between **Continuous** scrolling and **Pages**. Large notes render in chunks; Pages provides previous/next controls and a page number. The layout preference is remembered.

The **book icon** in the desktop Settings header opens Nova’s README on GitHub in your default browser.

Settings also offers **Galaxy performance**: **High performance** animates hovered and focused glows at up to 60 FPS; **Saver** uses up to 24 FPS and settles effects when you pause. Turn off **Show tooltips** in Settings to hide hover hints.

Galaxy mode also enables motion and glow around the focused workspace. Click the Nova emblem for a three-second **Supernova** effect around the window, even with Galaxy mode off. Reduced-motion preferences replace the burst animation with a steady rim that clears afterward.

Scroll above the first line or below the last line to make room around your note. This blank space is bounded by the viewport size and does not grow as you scroll; the title stays visible at the upper scroll limit. Open editor tabs retain their scroll position when switching files. On mobile, the scroll space stays fixed while the software keyboard changes height, and bottom navigation hides while editing.

Collapse navigation, bookmarks, top bars, or the status bar with the edge controls. Drag a side-panel divider to resize it; double-click to reset. Focused dividers support arrow keys (Shift for larger steps), Home/End, and Enter to reset. Panel widths and visibility are remembered. **Command-G / Ctrl-G** toggles focus mode: entering hides all panels, and exiting expands them all, including any previously collapsed panels. The exit control does the same.

In Markdown **Edit** mode, typing these shortcuts applies formatting immediately:

| Type | Result |
| --- | --- |
| `- `, `* `, or `+ ` at the start of a paragraph | Bulleted list |
| `1 `, `1. `, or `1) ` at the start | Numbered list; a number followed by `.` or `)` can start above 1 |
| `[ ] ` or `[x] ` at the start, including after a bullet | Unchecked or checked task |
| `# ` through `###### ` at the start | Heading levels 1–6 |
| `> ` at the start | Quote |
| Three backticks or `~~~`, then Space or Enter | Code block; optionally add a language name before Enter, such as `ts` or `python` |
| `---` at the start | Horizontal rule |
| `**bold**`, `*italic*`, `~~strike~~`, or backticks around text | Bold, italic, strikethrough, or inline code |
| `->` or `<-` | Right arrow (→) or left arrow (←), immediately without a trailing space; Backspace restores the typed characters |

The trailing spaces above are part of the shortcut. Press Backspace immediately after a Space-triggered conversion to restore the typed marker. Enter continues a list; Enter on an empty item exits it. Markers inside code remain literal. Source mode keeps Markdown syntax visible; these automatic conversions apply to formatted Edit.

In `.txt` files, typing `->` or `<-` also inserts → or ← immediately. Press Backspace immediately, or Undo, to restore the original characters. Existing text, pasted text, and dictation stay literal.

Formatting buttons highlight the formats active at the cursor or across the selection in Source and formatted Edit. The formatting toolbar includes Undo/Redo, headings 1–6, bold, italic, strikethrough, inline code, code blocks, ordered and unordered lists, tasks, and quotes. In Markdown notes, Command/Ctrl-B and -I apply bold and italic; Command/Ctrl-Shift-X applies strikethrough. Command/Ctrl-Alt-1 through -6 apply headings, and -0 returns to normal text. Command/Ctrl-Shift-7, -8, and -9 apply numbered lists, bullets, and quotes. In formatted Edit, Tab / Shift-Tab nest or outdent list items; in Source, they indent or outdent Markdown by four spaces. Source formatting preserves existing indentation, and Read mode recognizes nested numbered lists that start above 1. Command-A / Ctrl-A selects the whole focused document, including nested lists. Source selection highlighting covers line breaks and blank lines; energy effects follow the selected passage in Source and the fallback reader.

Use **Inline code** for short snippets, or surround text with single backticks; typing the closing backtick applies the format. Use the adjacent **Code block** button (Command/Ctrl-Alt-C) for multiline code. In Edit, it toggles the current paragraph or selected blocks; Enter adds a code line, and three Enters at the end return to normal text. In Source, it adds fences around the current or selected lines; clicking it inside a fenced block removes the fences. The button highlights while the cursor is in a code block (a fenced block in Source).

## Terminal

The desktop app includes terminal tabs below the note. Open them with the terminal icon above the note, **Terminal** in the status bar, or **Command-Down / Ctrl-Down**. The browser preview displays an explanation instead of starting a shell.

- **Sessions**: the first shell starts when you first open the terminal. Use **+** to start another session in the active note folder, or your home directory in the sample workspace. Existing sessions keep their own working directory when you switch notes or folders.
- **Tabs**: switching tabs or collapsing the tray keeps each shell and its output alive. Closing a terminal tab ends its shell; closing the Nova window ends that window's shells. Sessions are not restored after restart. Each tab retains up to 5,000 lines of scrollback.
- **Sizing**: drag the top divider, empty tab-bar area, or status-bar background. Drag toward the bottom edge to collapse; use the maximize button for more room. Nova remembers the normal tray height. Double-click the divider to reset it.
- **Keyboard resizing**: focus the divider and use Up/Down, with Shift for larger steps. Home collapses, End expands to the maximum, and Enter resets the height.
- **Shell**: Mac uses the shell configured by `SHELL` as a login shell (falling back to `/bin/sh`); Windows uses `COMSPEC` (falling back to `cmd.exe`). Commands run with your normal user permissions.

**Panel shortcuts**: Command + arrow keys on Mac, or Ctrl + arrow keys on Windows, toggle navigation (Left), bookmarks (Right), top bars (Up), and terminal (Down). They also work inside editors and terminals; Shift-modified shortcuts retain their normal selection behavior. Panel shortcuts are suspended while app dialogs or search are open. Top bars use their toggle control rather than drag resizing.

## Tabs

Single-click an explorer filename to open it, or activate its focused button with the keyboard. Single-clicking a new file opens an italic preview tab, replacing an existing preview even when a fixed tab was active. Double-click the explorer filename or preview tab, or edit the note, to keep it open as a fixed tab. Double-clicking a fixed tab opens the rename dialog. Opening an already open file selects its existing tab. Close tabs with their × button or Command-W / Ctrl-W. Unsaved tabs, including inactive tabs with recovery drafts, offer **Save**, **Discard**, and **Cancel**. Save writes the note before closing; Discard removes its unsaved draft; Cancel keeps it open. A save failure leaves the tab open. Switching tabs retains recovery drafts.

Drag a tab label left or right with a mouse or pen to reorder tabs. An insertion marker shows the destination, and dragging near either edge scrolls the tab strip. Escape, losing window focus, or releasing outside a valid tab strip or pane drop target cancels the move. Reordering preserves the active note and preview status; the order is restored after restart. Touch gestures keep their normal scrolling behavior.

On desktop, open at least two tabs and choose **Split editor right** to move the current note into a second pane. You can also drag a tab to another pane's tab strip or to a pane's left, right, top, or bottom edge to split it. Drag a file directly from the Explorer or Starred files into a pane or onto an edge, without opening it first. Dropped files stay open as fixed tabs; dragging an already-open file moves its existing tab. Press Escape or release outside the editor to cancel. Drag the divider to resize panes, double-click it to balance them, or focus it and use the arrow keys. Closing or moving the last tab in a pane removes that pane. The layout is remembered across restarts. Compact mobile layouts show one pane at a time with an **Open files** picker. Tap the file bar to choose or close an open file; drag left/right anywhere across the editor or file bar to slide between open files, with both panels visible during the gesture. Swipes cycle between the last and first file; short drags snap back. See [mobile touch controls](mobile.md#touch-editing-and-open-files) for creation, explicit rename confirmation, formatting, and keyboard dismissal.

Each pane keeps its selected editor mounted. Click a pane to make it active for bookmarks and note actions. The Source, Edit, and Read controls apply across panes, adapting to each file type. Switching tabs reveals the active file in the explorer, expands its parent folders, and scrolls it into view. Open tabs keep in-memory editor states for cursor position and undo history; these are released when closed or replaced. External file changes invalidate the cached state on reopening. Restarting restores the ordered tab list, active note, editing mode, explorer folders, and collapsed directories. Desktop drafts are written atomically to the app-data `drafts` directory on each edit, independently of the development server port; the status bar confirms when the write finishes. Browser previews use local storage. Drafts are stored per folder and file on this device, including after their tabs close, and follow file renames and moves within Nova. Explicit Save clears a draft after the file and anchors are written. Recovery writes can fail if storage is unavailable or full; failures are reported and normal desktop close/quit is blocked until edits can be preserved or saved.

## Voice typing

Click the **Dictate** microphone icon in the document toolbar. Hover or focus it to see voice-typing status and the recording timer. On Mac, **Command-Shift-D** starts or stops dictation, including while an input or terminal has focus. Command-V keeps its normal Paste action. Windows keeps Ctrl-V for paste and uses the microphone button for dictation. On first use, download the English Whisper tiny.en model (77,704,715 bytes, about 78 MB) from the upstream whisper.cpp Hugging Face repository. Nova checks the download's SHA-256 before installing it in its OS app-data `speech` directory. The model is not bundled into the app or committed to Git.

Place the cursor where you want to write, press **Dictate**, allow microphone access, speak, then click the stop icon to finalize the transcript. Live previews appear with a short processing delay and can change as more audio is processed. Nova uses the system's default microphone and inserts the transcript at the original insertion point (which follows intervening edits). Voice typing inserts text; it does not replace a selected passage. Each transcript is a separate undo step and existing bookmarks continue to track edits. A recording stops automatically after two minutes.

**Cancel** discards the recording/result and removes unedited preview text. If you edit the preview itself, Nova keeps your version and stops replacing it with later speech results. File and folder switching and app close/quit are blocked during active dictation so a result cannot land in another note. Save the inserted text with the usual Save command. Live previews do not add undo steps; the finalized transcript is inserted as one undoable change.

Audio stays in memory on your machine; it is not written to disk or uploaded. Only the one-time model download uses the network. Audio is downmixed/resampled to 16 kHz mono and capped at 7.68 MB; Whisper loads for the dictation session, reuses one decoder for partial and final transcripts, uses up to four CPU threads, and is released afterward. Transcription has an additional temporary memory cost that has not yet been benchmarked. This first model is English-only; accuracy varies with speech, background noise, and microphone quality.

On macOS, allow Nova in **System Settings → Privacy & Security → Microphone** if needed. On Windows, enable microphone access for desktop apps under **Settings → Privacy & security → Microphone**. The browser preview explains the feature but does not record; voice typing requires the desktop build. Use the arrow next to Dictate to reopen voice settings or download the model again if it becomes corrupted. A load error leaves the note untouched.

The speech engine can be checked with a known public JFK audio fixture without opening a microphone:

```sh
cargo test --manifest-path src-tauri/Cargo.toml actual_whisper_transcription -- --ignored --nocapture
```

This explicit integration test checks partial and final transcription and cancellation using downloaded audio, without opening a microphone. It downloads the model and fixture into a temporary directory; set `NOVA_SPEECH_TEST_MODEL` to an existing model file to reuse it. Normal tests do not download a model or request microphone access.

## Bounds and current limitations

- Up to 32 MiB per UTF-8 text file. Local browsing has no total file-count limit; directories are loaded in pages. Cloud spaces retain the 50,000-note limit. Filename and content searches run asynchronously across unopened directories; broad searches in very large trees can take longer. Recents remembers up to 100 local folders.
- Rich document editing is limited to notes up to 500,000 characters; larger notes use the source editor. Read mode paginates documents over 500,000 characters and prepares Markdown in a background worker. Pages preserve Markdown blocks and cross-document references; bookmarks jump to the corresponding page. Task checkboxes remain interactive in the paginated reader, and toggling one preserves the current page. The full source and parsed document still reside in memory, and a single oversized Markdown block stays together on one page.
- Text search streams saved files, returns at most 80 matches, and cancels superseded searches between reads. It skips files over 32 MiB and invalid UTF-8 content. `.git`, `.obsidian`, `node_modules`, `target`, and `.Trash` directories are excluded, and directory symlinks are not followed.
- External Local detection uses native, nonrecursive directory watches for open files, expanded directories, and their parents. It does not index or recursively watch the whole repo. Unrelated file-content changes and generated-directory activity are ignored, except for explicitly opened files. Filesystems that do not supply native events may require refocusing the window or manually refreshing and reopening a file. Watcher errors are reported; missed-event notifications trigger reconciliation. Up to 4,096 open-file/expanded-directory targets can be watched per window; the total number of unopened files is not this limit. No image attachments or plugin compatibility yet. Clean open notes also refresh after Drive downloads. Desktop and iOS Google Drive check selected paths for incoming changes every minute and preserve both sides of conflicting edits. Deletions do not propagate, and automatic conflict merging is not available.
- Fonts are bundled locally. Markdown raw HTML is not executed. Image rendering is deliberately a placeholder in this first version.
- On Windows, native directory watches can prevent renaming a watched folder or one of its ancestors. Close the Nova windows using that folder before moving or renaming it externally, then reopen it at its new path.
- RAM targets are not benchmarked yet. Tauri's webview subprocesses must be included in any measurement.

## Code editing

Open or rename a file with a supported extension to enable code assistance automatically:

| Language | Extensions |
| --- | --- |
| Python | `.py`, `.pyw`, `.pyi` |
| TypeScript | `.ts`, `.mts`, `.cts`, `.tsx` |
| JavaScript | `.js`, `.mjs`, `.cjs`, `.jsx` |
| Java | `.java` |
| JSON | `.json`, `.map` |
| HTML | `.html`, `.htm` |
| CSS | `.css` |

The status bar shows the detected language. Code files have syntax highlighting, bracket matching and automatic closing, automatic indentation, and folding controls in the gutter. Spelling checks are disabled for code. Markdown and other text files retain their writing behavior.

Suggestions appear as you type. Press **Ctrl Space** to request suggestions, use the arrow keys to choose one, and **Enter** to accept it. **Escape** dismisses suggestions. **Tab / Shift Tab** indent and unindent code; press **Escape**, then **Tab** to move keyboard focus out of the editor. Python and JavaScript/TypeScript include local-name suggestions; Java includes keywords and class/main snippets. Suggestions also include words from the current document. Completion does not resolve project imports or library APIs.

Basic syntax errors are underlined and marked in the gutter; hover over a marker for details. **⌘ Shift M** (Mac) or **Ctrl Shift M** (Windows) opens the diagnostics panel. JSON uses JSON parsing errors; other languages report syntax the editor's grammar cannot parse. These checks are intentionally limited: they are not compiler validation, type checking, or style linting, and may miss invalid code. Syntax diagnostics are skipped above 200,000 characters and limited to 100 markers for grammar errors to keep editing responsive.

Code assistance runs locally and requires no Python, Node, or Java installation. Nova does not yet run code, debug, provide project-wide analysis, or connect to language servers. Markdown code fences do not use this code-editing mode.

## App updates

Desktop Nova checks for a newer version shortly after launch and whenever Settings opens. A top-left update icon opens Settings when an update is available. Settings shows check progress, errors, and a **Check for updates** button to retry. When available, open **Update Nova** in Settings and choose **Download update**. You can continue writing during the download. Choose **Restart to update** to install; Nova first preserves the session and recovery draft. Finish voice typing and close other Nova windows before restarting. Terminal sessions end on restart. See the [update guide](app-updates.md) for release and verification details.
